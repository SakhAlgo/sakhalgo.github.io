## Концепция проекта

### Название: **«TKD Master»**

Интеллектуальная платформа, объединяющая тхэквондо, технологии и искусственный интеллект для повышения эффективности тренировок детей, вовлечённости родителей и профессиональных возможностей тренеров.

### Ключевые компоненты

| Компонент | Описание | Целевая аудитория |
|-----------|----------|-------------------|
| **Фронтенд** | Мобильное приложение (React Native) + веб-панель. Детский интерфейс — игровой с аватарами и достижениями. Родительский — аналитика прогресса. Тренерский — управление группами и анализ техники. | Дети 6–14 лет, родители, тренеры |
| **Бэкенд** | Микросервисная архитектура: управление пользователями, хранение видео и статистики, API для ИИ-сервисов, система уведомлений. | — |
| **ИИ-сервисы** | 1) Анализ техники через компьютерное зрение<br>2) Персонализированные рекомендации упражнений<br>3) Прогнозирование времени до следующего пояса | — |

### Уникальные преимущества

- **Для детей**: Геймификация (аватары, квесты, достижения) повышает мотивацию и удержание в спорте.
- **Для родителей**: Объективная аналитика прогресса вместо субъективных ощущений «он стал лучше».
- **Для тренеров**: Инструменты для массового анализа техники группы, выявления слабых мест учеников.
- **Для школ**: Повышение лояльности клиентов за счёт цифровых сервисов и снижения оттока.

### Монетизация (кратко)

1. Подписка школ (B2B): €49–129/месяц  
2. Дополнительные услуги родителям через школу (B2C2B): €3–10/месяц

## Архитектура ИИ-сервисов

### 2.1. Анализ техники (Computer Vision)

#### Архитектура обработки

```
Видео с телефона → Поза-детекция (MediaPipe) → 3D-скелет → 
Анализ биомеханики → Оценка по критериям → Рекомендации
```

#### Ключевые метрики оценки

| Элемент техники | Метрики анализа | Целевые значения |
|-----------------|-----------------|------------------|
| **Удары ногами** | Траектория стопы, пиковая скорость, высота подъёма колена, баланс опорной ноги | Скорость > 2.5 м/с, угол колена > 140° |
| **Стойки** | Углы суставов (бедро-колено-лодыжка), распределение веса, отклонение центра масс | Отклонение < 15° от вертикали |
| **Повороты корпуса** | Амплитуда вращения, стабильность таза, синхронизация рук/ног | Амплитуда > 90°, дрейф таза < 10 см |

#### Технологический стек и сложность

| Компонент | Технология | Сложность | Время разработки |
|-----------|------------|-----------|------------------|
| Поза-детекция | Google MediaPipe Pose (бесплатно) | ⭐⭐ Низкая | 2 недели |
| 3D-реконструкция | MediaPipe 3D + калибровка по полу | ⭐⭐⭐ Средняя | 1.5 месяца |
| Анализ техники | Правила + ML-классификатор ударов | ⭐⭐⭐⭐ Высокая | 3 месяца |
| Оценка качества | Сравнение с эталонными движениями | ⭐⭐⭐⭐⭐ Очень высокая | 4+ месяца |

#### Ресурсы и риски

| Параметр | Оценка |
|----------|--------|
| **Время разработки MVP** | 6–9 месяцев |
| **Команда** | 2 CV-инженера + 1 бэкенд-разработчик + 1 тренер-консультант |
| **Стоимость** | $80–150 тыс. (зарплаты + сбор данных) |
| **Критический путь** | Сбор и разметка 5 000+ видео ударов разных уровней подготовки |
| **Главный риск** | Низкая точность на домашнем видео (плохое освещение, неудачный ракурс) |

> **Реалистичный подход**: Начать с анализа **статических стоек** (точность >90%), затем добавлять динамические удары. Это позволяет выйти на рынок за 4 месяца вместо 9.

### 2.2. Персонализированные рекомендации (ИИ-тренер)

#### Архитектура генерации плана

```python
Данные пользователя → Вектор слабых мест → 
Поиск упражнений в базе знаний → Генерация персонального плана → Адаптация под прогресс
```

#### Уровни реализации

| Уровень | Технология | Точность | Сложность | Время |
|---------|------------|----------|-----------|-------|
| **Базовый** | Правила «ЕСЛИ-ТО» (например: «если низкий удар → упражнения на гибкость») | 60% | ⭐ Низкая | 1 месяц |
| **Средний** | Коллаборативная фильтрация (аналогия с пользователями, имеющими похожие ошибки) | 75% | ⭐⭐⭐ Средняя | 2 месяца |
| **Продвинутый** | Fine-tuning LLM на базе знаний тренеров + обучение с подкреплением | 85%+ | ⭐⭐⭐⭐⭐ Очень высокая | 6+ месяцев |

#### Пример базы знаний для правил

```yaml
ошибка: "недостаточная высота апчаги (удар ногой вверх)"
  причины:
    - "слабые мышцы кора"
    - "недостаточная гибкость приводящих"
  упражнения:
    - "планка 30 сек × 3 подхода"
    - "мостик с задержкой 15 сек"
    - "растяжка паха у стены"
  прогрессия:
    - "удар у стены → удар с поддержкой партнёра → свободное выполнение"
```

#### Ресурсы

| Параметр | Оценка |
|----------|--------|
| **Время разработки** | 2–3 месяца (базовый), +4 месяца (ML-версия) |
| **Команда** | 1 ML-инженер + 1 тренер для составления правил |
| **Стоимость** | $25–40 тыс. |
| **Требуемые данные** | 200+ профилей учеников с разметкой ошибок техники |

> **Совет**: Стартовать с **гибридного подхода** — правила + простая коллаборативная фильтрация. Это даёт 80% результата при 20% затрат.

### 2.3. Прогнозирование достижения поясов

#### Модель прогноза

```
Фичи → Модель машинного обучения → Вероятность сдачи через N недель
```

**Входные признаки (фичи):**
- Частота тренировок (дни/неделю)
- Динамика оценок ИИ по технике за последние 3 месяца
- Возраст, пол, начальный уровень подготовки
- История пропусков тренировок
- Участие в спаррингах и турнирах

**Архитектура модели:**
- **Базовый вариант**: Логистическая регрессия / XGBoost (интерпретируемо, быстро обучается)
- **Продвинутый**: LSTM для анализа временных рядов прогресса ученика

#### Пример вывода для родителя

> **Прогноз сдачи на жёлтый пояс**  
> 📅 Ожидаемая дата: 15–28 марта 2026  
> ✅ Сильные стороны: удары ногами (+15% за месяц)  
> ⚠️ Зона роста: формы (пульсары) — рекомендуем 2 дополнительные тренировки на этой неделе  
> 📊 Вероятность успешной сдачи: 82%

#### Ресурсы

| Параметр | Оценка |
|----------|--------|
| **Время разработки** | 1.5–2 месяца |
| **Команда** | 1 Data Scientist |
| **Стоимость** | $15–25 тыс. |
| **Требуемые данные** | Минимум 300 историй сдачи поясов (время тренировок → результат экзамена) |

> **Важно**: Прогнозы должны быть **консервативными** и сопровождаться дисклеймером: *«Прогноз основан на статистике. Финальное решение о готовности принимает тренер»*. Это снижает юридические риски.

## Архитектура бэкенда

### 4.1. Микросервисная структура

```
┌─────────────────────────────────────────────────────────────────────┐
│                         API Gateway (Traefik)                       │
└──────────┬──────────────────────┬──────────────────────┬───────────┘
           │                      │                      │
    ┌──────▼──────┐       ┌───────▼───────┐      ┌───────▼───────┐
    │  Auth       │       │  Video        │      │  User         │
    │  Service    │       │  Service      │      │  Service      │
    └──────┬──────┘       └───────┬───────┘      └───────┬───────┘
           │                      │                      │
    ┌──────▼──────────────────────▼──────────────────────▼──────┐
    │                   Message Queue (Redis Streams)           │
    └──────┬──────────────────────┬──────────────────────┬──────┘
           │                      │                      │
    ┌──────▼──────┐       ┌───────▼───────┐      ┌───────▼───────┐
    │  CV Worker  │       │  Recs Engine  │      │  Forecast     │
    │  (MediaPipe)│       │  (XGBoost)    │      │  (LSTM)       │
    └─────────────┘       └───────────────┘      └───────────────┘
           │                      │                      │
    ┌──────▼──────────────────────▼──────────────────────▼──────┐
    │                    Storage Layer                           │
    │  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐  │
    │  │ PostgreSQL  │  │ MinIO/S3     │  │ Redis (cache)    │  │
    │  │ (users,     │  │ (videos,     │  │ (sessions,       │  │
    │  │  progress)  │  │  frames)     │  │  queues)         │  │
    │  └─────────────┘  └──────────────┘  └──────────────────┘  │
    └───────────────────────────────────────────────────────────┘
```

#### Описание микросервисов

| Сервис | Технология | Ответственность | SLA |
|--------|------------|-----------------|-----|
| **Auth Service** | Node.js + JWT | Регистрация, роли (ребёнок/родитель/тренер), управление правами доступа | 99.9% |
| **Video Service** | Python + FFmpeg | Приём видео, обрезка до 10 сек, конвертация в 720p, генерация превью | 99.5% |
| **CV Worker** | Python + MediaPipe + TensorFlow Lite | Асинхронный анализ позы → расчёт метрик → сохранение результатов | 95% (асинхронный) |
| **Recs Engine** | Python + Scikit-learn | Генерация персонального плана тренировок на основе ошибок | 99% |
| **Forecast Service** | Python + XGBoost/LightGBM | Прогноз времени до следующего пояса | 98% |
| **Notification Service** | Node.js + Firebase Cloud Messaging | Push-уведомления, email-отчёты родителям | 99% |

### 4.2. Критические технические решения

| Проблема | Решение | Обоснование |
|----------|---------|-------------|
| **Медленная загрузка видео** | Сжатие на клиенте через ffmpeg.wasm до 15 МБ (10 сек, 720p) | Экономия трафика пользователей, ускорение обработки |
| **Длительный анализ (>30 сек)** | Асинхронная обработка через Redis Streams + прогресс-бар в приложении | Не блокирует пользовательский интерфейс |
| **Дефицит данных для обучения** | Синтетические данные через Blender (анимация ударов) + разметка тренеров-партнёров | Ускорение старта до сбора 5 000 реальных видео |
| **Высокая стоимость хранения** | Автоматическое удаление исходных видео после анализа; хранение только ключевых кадров + числовых метрик | Снижение стоимости хранения на 90% (с $0.50 до $0.05 на видео) |

#### Пример потока обработки видео

```python
# POST /api/v1/analysis
1. Клиент загружает видео (15 МБ, 10 сек)
2. Video Service сохраняет в MinIO, публикует событие в Redis Stream
3. CV Worker (асинхронно):
   - Извлекает 30 кадров (3 кадра/сек)
   - Запускает MediaPipe → получает 33 ключевые точки на кадр
   - Вычисляет метрики:
        * Баланс: отклонение центра масс от опорной ноги < 15°
        * Амплитуда: угол в колене при ударе > 140°
        * Скорость: пиковая скорость стопы > 2.5 м/с
   - Сохраняет результаты в PostgreSQL
4. Recs Engine генерирует 3 упражнения на основе выявленных ошибок
5. Notification Service отправляет пуш-уведомление родителю:
   «Саша улучшил баланс на 12%! Рекомендуем упражнение "Ласточка" 2 раза в день»
```

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| **Низкая точность анализа на домашнем видео** | Высокая | Среднее | Требовать съёмку у стены с визуальными маркерами (линия пола); ручная верификация тренером первые 3 месяца |
| **Юридическая ответственность за рекомендации** | Средняя | Высокое | Дисклеймер в приложении: «Рекомендации дополняют, но не заменяют работу тренера»; страхование ответственности |
| **Недостаток данных для обучения ИИ** | Высокая | Высокое | Партнёрство с федерацией тхэквондо для доступа к видеоархивам; синтетические данные через Blender |
| **Отказ родителей платить за «цифрового тренера»** | Средняя | Среднее | Позиционировать как инструмент **для тренера**, а не замену; школа включает стоимость в абонемент |
| **Конкуренция с аналогами (например, приложения для йоги)** | Низкая | Низкое | Узкая специализация на тхэквондо + партнёрство с федерацией как барьер для входа |

## Рекомендации для старта

### Главный принцип

> **Не стройте «идеальный ИИ» — стройте «полезный инструмент для тренера»**

### Пошаговый подход к запуску MVP за 4 месяца

| Месяц | Задача | Бюджет | Результат |
|-------|--------|--------|-----------|
| **1** | Бэкенд: Auth + Video Service + PostgreSQL | €8 000 | API для загрузки и хранения видео |
| **2** | Интеграция MediaPipe (анализ статических стоек) | €12 000 | Оценка баланса и углов суставов с точностью >85% |
| **3** | Мобильное приложение (React Native) + правила рекомендаций | €15 000 | Родитель получает отчёт после тренировки в течение 2 минут |
| **4** | Пилот с 3 школами + итерации по фидбэку | €5 000 | 100+ видеоанализов, подтверждённая потребность, дорожная карта v2.0 |

> **Итого MVP**: €40 000 за 4 месяца  
> **Команда**: 1 бэкенд (€3к/мес) + 1 фронтенд (€2.5к/мес) + 1 CV-инженер (€4к/мес, частично)

### Гибридная модель обучения ИИ (снижение рисков)

1. Первые 3 месяца — тренер вручную размечает видео через ваш интерфейс (оценивает удары по шкале 1–5)
2. Параллельно собираются данные для обучения модели
3. На 4-м месяце запускается бета-версия ИИ с пометкой *«Экспериментальная оценка»*
4. Тренер подтверждает или корректирует оценку ИИ → модель обучается на его правках (human-in-the-loop)

**Преимущества подхода:**
- ✅ Ранний продукт для продажи уже на 2-м месяце
- ✅ Качественные размеченные данные для обучения ИИ
- ✅ Доверие тренеров (они контролируют процесс, а не доверяют «чёрному ящику»)
